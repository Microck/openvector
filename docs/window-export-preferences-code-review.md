# Export widget preference evidence

The independent implementation must account for source events and synchronization,
not just store six unrelated widget records. Native observations prove separate
formats and restored folders, a shared bitmap scale, and later folder replacement
on image load and application-model reset. No production implementation is added
before those ownership rules are established.

The corpus contains 21 cases, each repeated in a fresh process. It retains 65
reference snapshots, each with 16 widgets, and 130 executed snapshots including
repeats. The existing observer reads fields and Qt getters. The driver seeds only
its guarded private registry namespace. It does not operate a native control,
answer a dialog or run the window writer. Original files, saved settings and the
input desktop are checked before and after each process.

Initial seeds used groups for extension, directory, scale and minimize-on-drag.
Those fields were ignored. REA and exact assembly show that the native key helper
concatenates the widget identifier and field name without a separator. Expansion
uses a separate prefixed group. The initial script and raw recordings remain as
rejected restoration evidence; the corrected captures have new names.

The common capture driver gains an explicit optional working directory for the
second directory-context case. Existing cases still use the same root. This
changes no native helper, wire operation, parser or product path. The export
recorder verifies the stored context before accepting resumed proofs.

REA completed ten owner/key/reader decompilations. A follow-up used the unsupported
name `get_callers`, which caused the client to exit. Saved result files remain
available. The prior analysis snapshot is preserved, but this turn does not claim
a new snapshot. The analysis processes are closed.

The existing batch comparison was inspected without widening its contract. Its
raw setter value 2 is outside the observed public menu values 0, 1 and 3. The
failure remains visible. No assertions, fixtures or product validation were
changed to conceal it.

Simplification reviewed the recorder and the common driver's one-line context
change with the reuse, quality and efficiency rubrics inline. Applied: reuse 0,
quality 1, efficiency 0. The quality change checks every declared case input when
resuming, including working directory. Skipped: one proposal to merge semantic
and raw audits; keeping the existing shared audit contract avoids unrelated
changes for negligible audit cost. There were zero independent reviewer contexts.
No unused production elements were introduced. There are no configured lint or
typecheck scripts.

Production engine, CLI, package files, GUI, current preview build and all 27
accepted native helpers remain unchanged. The new fixture is reference evidence,
not a claim that OpenVector already implements these controls. Quick Save, bitmap
render/export, drag-result behavior, persistence, full reset and shutdown still
require implementation or further verification.
